# Prepare evidence

Prepared 2026-09-26. The fixed corpus contains 120 distinct 3-SAT formulas: 20 hand cases and 100 seeded random cases, with 64 YES and 56 NO. Formula sizes range from 0 to 6 variables. `generate_cases.py` fixes inputs and seeds before construction.

Run `uv sync --locked` and `uv run --locked python campaigns/two-tree-mixed-layout-recognition/work/check.py --self-test`. It first runs the copied `research/validate_preparation.py`, regenerates random formulas, recomputes Z3 SAT labels, validates assignments directly and compares with exhaustive Boolean assignments. A target graph is checked as a 2-tree by repeatedly removing a degree-two simplicial vertex until only an edge remains. The target Z3 encoding chooses a vertex-order permutation and one Boolean page per edge, forbidding alternating independent stack edges and nested independent queue edges. Every model is validated by a direct order/page predicate. Full order and page enumeration agreed for 75 seeded 2-trees of two through five vertices. Hand checks include invalid 2-trees, crossing stack edges and nested queue edges. A deliberately incorrect candidate returning a feasible edge target and always extracting NO-SOLUTION was rejected.

Oracle: CPython 3.12.14 and locked `z3-solver` 4.16.0.0. Only Z3 `unsat` yields a negative result; `unknown` raises. The finite exhaustive crosscheck covers up to five vertices; it does not include a target 2-tree without a mixed layout. The candidate gate checks at most three target layouts per source case and cannot establish universal recovery. Prepare remains partial until a target 2-tree with no mixed layout is encoded and checked. No reduction or solution is claimed.
